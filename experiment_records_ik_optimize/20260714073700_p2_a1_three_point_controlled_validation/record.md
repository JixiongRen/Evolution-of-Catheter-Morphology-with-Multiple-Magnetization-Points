# P2 A1 三点受控外层验证记录

## 一、实验目的

本轮实验用于验证 A1 单点轴向磁化导管在三个代表点上的外层求解器稳定化策略。核心问题是：在局部灵敏度已经通过代表点审计后，可信通道子空间、真实末端优先接受、有限步长信赖域和回溯是否能减少 A1-pt12、A1-pt13 的大误差停滞，同时不破坏 A1-pt01 的已成功结果。

## 二、固定条件

- 导管类型：A1。
- 目标点：pt01、pt12、pt13。
- 重力：关闭。
- 离散化：`M_list=5`。
- 正运动学容差：`1e-5`。
- 成功阈值：最后刚性段远端真实末端误差不超过 `5 mm`。
- 电流边界：`[-20, 20] A`。
- 推进量边界：`[0.003001, 0.203] m`。
- 运行环境：`JAX_PLATFORMS=cuda`，图形处理器后端为 `cuda:0`。

## 三、运行内容

本轮包含三组结果：

1. 普通外层基线：不启用 P2 稳定化，不启用通道门禁。
2. 受控组无效试跑：启用 P2 与通道门禁，但发现门禁键名不匹配，所有通道被 `block_all` 禁用。
3. 受控组重跑：修复门禁键名后，重新启用 P2 与 A1 三点通道门禁。
4. pt01 消融一：启用 P2，但不启用通道门禁。
5. pt01 消融二：启用 P2 和通道门禁，但诊断性临时放行推进量通道。

代码修复提交：

- `419f018 Fix control gate point key normalization`

该修复将 `A1_pt13` 和 `A1_pt_13` 归一化为同一种点位键，避免审计表与实验入口之间的命名差异导致门禁匹配失败。

## 五、诊断结论

1. 门禁键名不匹配是一个已确认的工程缺陷。它会导致审计表匹配行数为 0，并在 `block_all` 策略下禁用所有控制通道。本轮已经修复该问题，并用真实 A1 门禁表验证：pt01、pt12、pt13 均能正确匹配 9 行记录。
2. 修复键名后，当前受控策略仍然没有通过 A1 三点门禁。最关键的证据是 A1-pt01 从普通外层的 `3.64 mm` 退化到 `27.79 mm`，说明该策略不能作为生产候选。
3. 受控组退化不能再解释为门禁键名错误。修复后通道已经正确放行，但推进量通道仍被禁用，因此当前更可能的问题是：保守通道门禁切断了必要的入盆自由度，或真实末端优先接受与可靠子空间组合导致求解器过早进入拒绝停滞。
4. A1-pt12 和 A1-pt13 的失败不能通过当前 P2 组合解决。pt12 甚至从 `50.59 mm` 退化到 `81.69 mm`，表明当前组合不应扩展到 A1 10 点或 20 点正式回归。
5. pt01 消融结果进一步定位了失败原因。启用 P2 但不启用门禁时，pt01 误差为 `3.61 mm`，仍然成功；启用门禁但诊断性临时放行推进量通道时，pt01 误差为 `4.38 mm`，也仍然成功。因此，pt01 退化的直接原因主要是当前保守通道门禁禁用了推进量通道，而不是 P2 的真实末端优先接受或回溯机制本身。
6. 推进量通道不能因此直接进入生产策略。当前 x 放行表是诊断探针，未通过正式灵敏度门禁。它只能说明“禁用 x 会破坏已成功点”，下一步应重新审计推进量通道或设计“入盆阶段允许 x、精修阶段再门禁”的分阶段策略。

## 六、下一步

下一步不进入 A1 扩点实验，而应先修正门禁策略：

1. 重新审计或重新定义推进量通道门禁，避免把入盆所需自由度直接删除。
2. 尝试两阶段策略：入盆阶段允许推进量参与，并限制电流和推进量步长；进入近邻域后再切换到严格审计通道。
3. 在修正门禁策略前，不运行 A1 十点或二十点正式回归。
