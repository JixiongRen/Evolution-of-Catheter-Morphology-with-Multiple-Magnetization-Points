# P2c38 分批加密扫描 eps=0.0125 可发布边界

## 实验目的

P2c37 表明 `alpha=0.420` 在 `eps=0.0125` 时仍因分支漂移失败，而 P2c36 表明 `alpha=0.425` 在同一扰动半径下可发布。本轮采用分批独立进程扫描 `alpha=0.421-0.424`，定位 `eps=0.0125` 从诊断样本转为可发布样本的边界。

## 实验方案

扫描点如下：

```text
alpha = 0.421, 0.422, 0.423, 0.424
eps = 0.0125
```

每个 `alpha` 使用独立 Python 进程运行，避免 P2c37 中出现的 JAX/LLVM 编译内存不足。每个子进程复用 P2c37 的候选分支逻辑，并输出独立 `summary.json`。

## 判定标准

- 基线静态门禁通过。
- 扰动后一阶最优性残差不超过 `1e-5`。
- 局部线性化误差不超过 `0.05`。
- 中心线分支漂移不超过 `1e-3 m`。
- 扰动后载荷传播比例不超过 `2`。

## 实验结果

本轮总墙钟时间为 `370.76 s`。四个 `alpha` 子任务均正常结束，单个子任务耗时约 `87.72-98.60 s`。

## 数据分析

本轮结果表明，在 `alpha=0.421-0.424` 的加密区间内，`eps=0.0125` 仍不能作为可发布扰动半径。四个样本的一阶最优性残差均远小于 `1e-5`，局部线性化误差也远低于 `0.05`，载荷传播比例均未超过门限。因此，失败原因不是优化未收敛，也不是一阶线性近似在末端位置指标上显著失效，而是扰动重求解后中心线形态进入了不同平衡分支。

从分支漂移看，`alpha=0.421` 和 `alpha=0.422` 处于临界附近，中心线均方根漂移分别为 `1.341 mm` 和 `1.017 mm`，仅略高于 `1 mm` 门限；`alpha=0.423` 和 `alpha=0.424` 的漂移增至约 `4.9 mm`，说明该区间存在明显的分支选择突变。该现象与 P2c37 中 `alpha=0.420` 的轻微失败、P2c36 中 `alpha=0.425` 的可发布结果共同说明：`alpha=0.420-0.425` 之间并非单调过渡，而可能存在由初值分支、目标生成路径和局部平衡 basin 共同决定的窄区间分支竞争。

因此，当前不能把 `eps=0.0125` 在该区间的有限差分敏感度作为高置信结果发布。较稳妥的工程解释是：此区域虽然末端响应的一阶数值量较小且线性误差表面上良好，但整体导管形态已经发生不可忽略的平衡分支切换。若后续外层逆运动学只依赖末端量，可能误判局部灵敏度连续；若要求导管形态也稳定，则应限制扰动半径或采用分支保持求解策略。

## 实验结论

1. `alpha=0.421-0.424` 在 `eps=0.0125` 下全部为诊断样本，不能发布高置信灵敏度。
2. 失败主因是中心线分支漂移超过 `1 mm`，不是一阶最优性残差、局部线性化误差或载荷传播比例失控。
3. `alpha=0.421-0.422` 是轻度临界区，`alpha=0.423-0.424` 出现明显分支漂移放大。
4. 当前证据支持将 `n3_mixed_rand20` 的安全扰动半径暂定为 `eps<=0.010`；`eps=0.0125` 只能在严格验证分支保持后局部使用。

## 下一步计划

下一轮不宜继续只做更密集的 `alpha` 标量扫描。更有信息量的方向是：

1. 对 `alpha=0.421-0.424` 做 `eps=0.010, 0.011, 0.012` 的扰动半径扫描，定位从可发布到分支漂移的扰动半径边界。
2. 对 `alpha=0.423-0.424` 做正负扰动分别检查，判断分支漂移是否具有方向性。
3. 增加分支保持约束或连续延拓重求解，验证失败是否可由求解路径修复。
4. 输出工程建议时，应将该区域标记为“多平衡分支竞争区”，对外层逆运动学限制步长，并要求每步做形态一致性复核。
